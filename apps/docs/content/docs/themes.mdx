wterm uses CSS custom properties for all visual styling, making it easy to switch between built-in themes or create your own.

On this site's homepage, **Default** follows your site theme: light, dark, or
system. The greeting and interactive terminal use the same colors, including in
fullscreen. Selecting Solarized, Monokai, or Light keeps that terminal preset
independent of the site theme. This site-specific Default does not change the
package's default dark palette described below.

## Using a Theme

### React

Pass the theme name via the `theme` prop:

```tsx
<Terminal theme="monokai" />
```

### Vue

Same `theme` prop:

```vue
<Terminal theme="monokai" />
```

### Svelte

Pass the theme name through the `theme` prop:

```svelte
<Terminal theme="monokai" />
```

### Vanilla JS

Add the theme class to the terminal element:

```js
const term = new WTerm(document.getElementById("terminal"));
term.element.classList.add("theme-monokai");
await term.init();
```

## Custom Themes

Create a custom theme by defining a CSS class that overrides the wterm custom properties:

```css
.wterm.theme-tokyo-night {
  --term-bg: #1a1b26;
  --term-fg: #c0caf5;
  --term-cursor: #f7768e;

  --term-color-0: #15161e;
  --term-color-1: #f7768e;
  --term-color-2: #9ece6a;
  --term-color-3: #e0af68;
  --term-color-4: #7aa2f7;
  --term-color-5: #bb9af7;
  --term-color-6: #7dcfff;
  --term-color-7: #a9b1d6;
  --term-color-8: #414868;
  --term-color-9: #f7768e;
  --term-color-10: #9ece6a;
  --term-color-11: #e0af68;
  --term-color-12: #7aa2f7;
  --term-color-13: #bb9af7;
  --term-color-14: #7dcfff;
  --term-color-15: #c0caf5;
}
```

Then apply it the same way as a built-in theme:

```tsx
<Terminal theme="tokyo-night" />
```

## Application color changes

Ghostty applications can set the default foreground, background, and cursor
colors with OSC `10`, `11`, and `12`. OSC `110`, `111`, and `112` reset the
corresponding color to the current CSS theme, including theme changes made
while an override was active. Explicit SGR cell colors are unaffected. Inverse
cells swap the actual foreground/background, including default colors, in both
cores.

Application overrides are separate from `--term-fg`, `--term-bg`, and
`--term-cursor`; the renderer never overwrites these host theme properties.
Updates follow normal rendering, including synchronized output and paused
panes. Destroying the terminal removes its overrides. The built-in core and
older Ghostty WASM binaries retain CSS theme defaults.

Ghostty color-query responses use its configured `foregroundColor` and
`backgroundColor` defaults; pass values matching your CSS theme. CSS changes
do not automatically update those headless defaults. See [Ghostty options](/ghostty).

## Font and cell alignment

Choose a monospace font with `--term-font-family` and set its size with
`--term-font-size`. wterm measures the font's cell width and uses it for text,
backgrounds, and cursors. Braille, box drawing, and other fallback glyphs stay
within their assigned columns even when the fallback font has wider glyphs.
Wide characters occupy two cells; oversized glyphs are clipped to their cells.
Common light, heavy, and rounded box-drawing characters connect across cell
edges even when the font's glyphs fall short. They remain selectable as text.

Cell widths update when fonts load or the font size changes, including when
`autoResize` is disabled. Native selection and OSC 8 link text are preserved.
This behavior is shared by both cores and all framework components.

## Cell backgrounds

Colored and reversed cells keep their backgrounds within their columns,
including the last column and rows in scrollback. A complete row with one
shared, opaque background extends that color to the container's right edge,
keeping full-width status bars filled. Mixed, dim, or hidden cells do not
repaint neighboring cells or other rows. This behavior is shared by both cores
and all framework components.
