## Options

The React, Vue, and Svelte `Terminal` components and the vanilla `WTerm` constructor accept the same core options — `cols`, `rows`, `core`, `wasmUrl`, `autoResize`, `maxImageWidth`, `maxImageHeight`, `cursorBlink`, `announceOutput`, `renderingPaused`, and `debug` — plus event callbacks `onData`, `onTitle`, `onBell`, and `onResize` (exposed as `@data`, `@title`, `@bell`, and `@resize` events in Vue).

See the full [API Reference](/api-reference#terminal-options) for types, defaults, and descriptions.

### Inactive panes

Set `renderingPaused: true` for a pane that is not visible. Change it with
`term.setRenderingPaused(paused)` in vanilla JavaScript, or the reactive
`renderingPaused` prop in React, Vue, and Svelte. The local workspace does this
automatically for inactive session tabs.

Paused panes keep parsing output, retaining history, resizing the core, and
delivering replies, titles, and bells. They stop scheduling terminal paints and
show the latest state on the next eligible frame after resuming. Output is not
queued for replay, and the PTY connection stays active. All terminals also pause
painting while their browser document is hidden; returning does not override
an explicitly paused pane.

The option controls rendering only: hosts still manage visibility, focus,
`inert`, and `aria-hidden`. CSS visibility alone does not set the option. New
search scans, `readText()`, and Select All wait for a paint before starting;
their existing cancellation rules still apply. Pending output announcements
are discarded on pause. Synchronized drawing continues to hold a frame until
the application ends the update or its recovery timeout expires.

### Scrollback rendering

Scrollback keeps a bounded window of mounted rows. As you scroll, overlapping
rows reuse their existing elements; unchanged text and links keep their DOM
nodes when new output arrives. This reduces DOM work while reading history
without changing selection, copy, or the amount of retained history. The
behavior is automatic for both cores and all framework bindings.

### PTY size

After `init()` or `resize()`, read `wt.cols` and `wt.rows` to size a connected
PTY. `onResize(cols, rows)` also receives the applied grid size. A core can
apply fewer cells than requested; the built-in core currently supports up to
1024 columns and 512 rows. Keeping the PTY at the applied size prevents its output from
wrapping at different columns than the browser terminal.

### Bell notifications

Both cores count BEL controls outside OSC sequences. `onBell(count)` runs as
output is written, even if synchronized output is holding a paint. Several
bells in one write chunk arrive as one count. WTerm leaves sound and visual
alerts to the host application.

### Cursor appearance

Both cores honor application requests for block, bar, and underline cursors
(DECSCUSR), plus cursor blink mode (`CSI ? 12 h/l`). This lets editors change
the cursor when switching between normal and insert mode. Unfocused terminals
show a steady outline, and hiding the cursor with mode 25 takes effect even
when no text changes.

Omit `cursorBlink` to follow the application (initially steady). Set it to
`true` to force blinking or `false` to keep the cursor steady, regardless of
application requests. React, Vue, and Svelte also support changing this prop
after mounting; set it back to `undefined` to follow the application again.
Cursor shape always follows the core. Custom cores can omit the optional
`CursorState.shape` and `blinking` fields for a steady block fallback.

### Pluggable cores

By default, wterm uses its built-in lightweight Zig WASM core (~26 KB). To use a different terminal emulation backend, pass a `TerminalCore` instance via the `core` option. See the [Ghostty Core](/ghostty) page for an example using libghostty.

Graphics support is optional on `TerminalCore`. The built-in core safely
consumes unsupported Kitty APC payloads without rendering image bytes;
`@wterm/ghostty` provides bounded direct Kitty PNG/RGB/RGBA rendering. Its
decoded image budget defaults to 32 MiB and can be disabled with
`imageStorageLimit: 0`. Use `maxImageWidth` and/or `maxImageHeight` to cap the
rendered dimensions of decoded images without changing that storage budget.
The DOM wrapper answers Kitty pixel geometry queries (`CSI 14 t` and
`CSI 16 t`) from the rendered terminal element and forwards the reports
through `onData`.

### React-only

The React `Terminal` component adds `theme`, `onReady`, and `onError` on top of the shared options. It also spreads standard HTML attributes onto the root `div`, so you can pass `className`, `style`, ARIA attributes, and other DOM props directly.

See [React-Only Props](/api-reference#react-only-props) for details.

### Vue-only

The Vue `Terminal` component adds a `theme` prop. `onReady` and `onError` are exposed as `@ready` and `@error` events instead of props. Standard DOM attributes (`class`, `style`, `id`, ARIA props, etc.) are forwarded to the root `<div>` via the default `inheritAttrs` behavior.

See [Vue-Only Props](/api-reference#vue-only-props) and [Vue Events](/api-reference#vue-events) for details.

### Svelte-only

The Svelte `Terminal` component adds the `theme` prop and forwards standard
`<div>` attributes such as `class`, `style`, `id`, and ARIA attributes. Svelte 5
applications can use the `onData`, `onTitle`, `onBell`, `onResize`, `onReady`, and
`onError` callback props.

See [Svelte-only Props](/api-reference#svelte-only-props) for details.

## Imperative Handle (React)

When using `useTerminal`, the returned ref exposes an imperative handle:

```tsx
import { Terminal, useTerminal } from "@wterm/react";

function App() {
  const { ref } = useTerminal();

  return (
    <Terminal
      ref={ref}
      onReady={(wt) => {
        wt.resize(120, 40);
      }}
    />
  );
}
```

See the full [Imperative Handle](/api-reference#imperative-handle-react) reference for all returned methods.

## Template Ref (Vue)

Access imperative methods on the Vue component via a template ref:

```vue
<script setup lang="ts">
import { useTemplateRef } from "vue";
import { Terminal, type WTerm } from "@wterm/vue";

const term = useTemplateRef("term");

function onReady(wt: WTerm) {
  wt.resize(120, 40);
}
</script>

<template>
  <Terminal ref="term" @ready="onReady" />
</template>
```

See the full [Template Ref (Vue)](/api-reference#template-ref-vue) reference for all exposed methods.

## Imperative Handle (Svelte)

Bind the Svelte component instance to call its imperative methods:

```svelte
<script lang="ts">
import { Terminal, type TerminalHandle } from "@wterm/svelte";

let terminal: TerminalHandle;
</script>

<Terminal bind:this={terminal} />
```

See the full [Imperative Handle (Svelte)](/api-reference#imperative-handle-svelte) reference for all exposed methods.

## WebSocket Transport

For connecting to a remote shell over WebSocket, use the built-in `WebSocketTransport`:

```ts
import { WTerm, WebSocketTransport } from "@wterm/dom";

const ws = new WebSocketTransport({
  url: "wss://your-server.example/shell",
  reconnect: true,
  maxReconnectDelay: 5000,
  onBackpressure(paused) {
    console.log(paused ? "Waiting for the connection to drain" : "Send buffer ready");
  },
  onData(data) {
    term.write(data);
  },
  onOpen() {
    console.log("connected");
  },
  onClose() {
    console.log("disconnected");
  },
});

const term = new WTerm(document.getElementById("terminal"), {
  onData(data) {
    try {
      ws.send(data);
    } catch (error) {
      console.error("Input was not sent", error); // Show this in your app's UI.
    }
  },
});

await term.init();
ws.connect();
```

See the full [WebSocketTransport](/api-reference#websockettransport) reference for all options, methods, and properties.

The transport buffers sends within configurable byte/message limits and drains
them in order. The defaults are 1 MiB across the transport and socket buffers,
and 1,024 messages waiting in the transport. Use `onBackpressure` to pause
producers and catch `RangeError` to report input that exceeded a limit. Explicit
`close()` discards unsent data; reconnect never replays bytes already handed to
the browser. See [Buffering and delivery](/api-reference#buffering-and-delivery)
for thresholds, lifecycle behavior, and delivery limits.

## Output announcements

Opt in with `announceOutput` to announce terminal text changes politely while
input has focus. The option defaults to `false`; component prop changes apply
without restarting the terminal, and vanilla callers use
`term.setOutputAnnouncements(enabled)`. Announcements are batched and stop
when focus leaves input. Bursts are bounded to avoid overwhelming the speech
queue. See [Output announcements](/api-reference#output-announcements) for
capture limits, pause/resume behavior, and redraw semantics.
