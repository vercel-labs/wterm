# Vanilla JS

The `@wterm/dom` package provides a framework-free terminal that works with plain HTML/CSS/JS.

## Install

```bash
npm install @wterm/dom
```

## Usage

```html
<div id="terminal"></div>

<script type="module">
  import { WTerm } from "@wterm/dom";
  import "@wterm/dom/css";

  const term = new WTerm(document.getElementById("terminal"), {
    onTitle(title) {
      document.title = title;
    },
  });

  await term.init();
</script>
```

## Custom Input Handling

By default, typed input is echoed back to the terminal. Pass `onData` when you need control over input — for example, sending it to a server:

```js
const term = new WTerm(document.getElementById("terminal"), {
  onData(data) {
    socket.send(data);
  },
});

await term.init();
```

## Options and Methods

The `WTerm` constructor accepts all [shared terminal options](/api-reference#terminal-options) (`cols`, `rows`, `core`, `wasmUrl`, `autoResize`, `maxImageWidth`, `maxImageHeight`, `cursorBlink`, `onData`, `onTitle`, `onResize`). Pass a [`TerminalCore`](/ghostty) instance to the `core` option to use an alternative emulation backend.

See [WTerm Methods](/api-reference#wterm-methods) for the full list of instance methods (`init`, `write`, `resize`, `focus`, `destroy`).

When a terminal application enables SGR mouse tracking or focus reporting, WTerm sends those reports through `onData` with keyboard input and host responses.

When the active core negotiates the Kitty keyboard protocol, WTerm encodes key presses, repeats, and available releases from the core's current flags. The built-in and Ghostty cores keep separate primary and alternate-screen flag stacks. Third-party cores without Kitty state retain legacy keyboard behavior.

Browsers do not expose every native keyboard field. WTerm uses `KeyboardEvent.code` for functional and modifier identity, `KeyboardEvent.key` for text, and reports shifted alternates when available. It does not invent a base-layout alternate, synthesize missing release events, or retain associated text beyond the current press.

Application-provided OSC 8 hyperlinks render as native anchors across both the active viewport and scrollback. Only absolute HTTP and HTTPS URIs become clickable; invalid, relative, and executable schemes remain ordinary terminal text.
While hovering an anchor, holding Command on macOS or Control on Windows and Linux reveals its underline and pointer cursor. Plain clicks remain terminal interaction. Command-click, Control-click, or native keyboard activation when an anchor receives focus opens the link. Modified link activation remains available while SGR mouse tracking is active and is not forwarded to the terminal application.

Scrollback normally uses a bounded DOM window around the visible rows. An active native text selection keeps its selected range mounted so the browser can preserve it. Native browser find and accessibility inspect the mounted window, not every retained history row. If the terminal is already at the bottom, new output keeps it at the exact bottom; reading older history does not enable auto-follow, and terminal input returns to the bottom.

### Terminal images

When the supplied core exposes the optional graphics methods, `WTerm` renders
visible pinned Kitty image placements in a separate canvas overlay. The overlay
is pointer-transparent, non-focusable, `aria-hidden`, and does not change
scroll height, so ordinary text selection, copy, keyboard input, and screen
reader behavior remain row-based. Image pixels are decorative; provide text
context separately when the image carries meaning.

For browser safety, every destination canvas is bounded by the active terminal
pixel area and all visible canvas backing stores share a 32 MiB budget. An
oversized or otherwise unmaterializable placement is skipped without changing
the text or scrollback surface.

The default lightweight core safely consumes unsupported Kitty APC data but
does not render it. Pass a Ghostty core for direct PNG/RGB/RGBA support. Images
are transient, bounded per-screen state; file/shared-memory/URL media, Sixel,
iTerm2, animation, and virtual placements are unsupported.
Use `maxImageWidth` and/or `maxImageHeight` in the `WTerm` options to constrain
oversized rendered images. The limits are CSS pixels, preserve aspect ratio,
and only scale images down.

The DOM wrapper answers Kitty pixel geometry queries (`CSI 14 t` and
`CSI 16 t`) from the rendered terminal element, allowing Kitty graphics clients
such as `kitten icat --transfer-mode=stream image.png` to negotiate image size.

## Themes

Import the stylesheet and apply a theme class to the terminal element:

```js
import "@wterm/dom/css";
```

Built-in themes: `theme-solarized-dark`, `theme-monokai`, `theme-light`:

```js
element.classList.add("theme-monokai");
```

All colors use CSS custom properties (`--term-fg`, `--term-bg`, `--term-color-0` through `--term-color-15`) so you can define your own theme with plain CSS.

## WebSocket Transport

Connect to a PTY backend over WebSocket:

```js
import { WTerm, WebSocketTransport } from "@wterm/dom";

const term = new WTerm(el, { cols: 80, rows: 24 });
await term.init();

const ws = new WebSocketTransport({
  url: "ws://localhost:8080/pty",
  onData: (data) => term.write(data),
});

ws.connect();
term.onData = (data) => ws.send(data);
```

See the full [WebSocketTransport](/api-reference#websockettransport) reference for all options, methods, and properties.
